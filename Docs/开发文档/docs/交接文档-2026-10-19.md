## 2. 关键排查结论（避免下一位重复踩坑）

### 2.1 「打怪完全不掉血」是误判 —— 伤害链路本来就是通的

实测证据（Play 模式下直接驱动状态机）：

- 玩家 `AttackHitbox` 命中盒 2.4×1.5、trigger、初始 disabled，靠 Animation Event 开关；
- `Player.controller` 里 `Attack / Attack02 / Attack03 / AttackAir / HeavyAttack` 五个状态**都带** `OnAttackWindowOpen` / `OnAttackWindowClose` 事件；
- 强制进入 `PlayerAttackState` 后：Animator 进入 Attack、命中盒 `_windowOpen=True`、敌人 HP 3→2；
- `Physics2DSettings` 图层矩阵 `0↔9` 未被禁用。

**结论：不是 bug，是缺少反馈导致肉眼以为没伤害。** 若今后再遇到「打不到」，按上述四点逐项复测即可。

### 2.2 uGUI 的 `Image.fillAmount` 必须挂 Sprite

`Image.Type.Filled` 在没有 `sprite` 时不会裁剪，`fillAmount` 静默无效、进度条永远画满。
**第一版小怪血条与既有的 `BossHealthBar` 都踩了这个坑**（Boss 血条历史上一直显示满格）。
统一解法：`UIUtility.WhiteSprite`。以后写任何进度条/血条都先 `image.sprite = UIUtility.WhiteSprite;`。

### 2.3 `SpriteRenderer.color` 无法用于闪白

`SpriteRenderer.color` 最终写入 Color32 顶点色，**超过 1 会被裁掉**。
实测：把颜色乘到 3.999，运行时读回确实是 `(3.999, 3.999, 3.999)`，但两张截图的同区域平均亮度是 127.0 vs 127.8 —— 画面毫无变化。
正确做法就是本轮的 `StarEco/SpriteFlash` 着色器。

### 2.4 Text 行高小于字号会导致整行不显示

`BossHealthBar` 的 Boss 名行高 29.04px、字号 26（单行行高约 31px），`UIUtility.CreateText` 默认 `verticalOverflow = Truncate` → 整行被裁掉，`Text.cachedTextGenerator.characterCountVisible` 恒为 **-1**。
排查手法：**同 Canvas 里新建一个测试 Text 做对照**。测试 Text 能显示 → 排除 Canvas/字体/层级；把原文本行高从 29 改成 60 能显示 → 确认是裁剪问题。
`characterCountVisible == -1` 就是「这个 Text 一个字形都没生成」的可靠信号。

### 2.5 Level02 相机「没跟上」是误判

`CameraFollow2D` 的合法范围由 `orthoSize(6.5) × aspect(1.777) = 11.55` 半宽推出：`minX=-16.45`、`maxX=16.45`（关卡边界 ∓28）。
玩家在 `x=-26`（出生点，已在边界外）时，相机钳在 `-16.45` 是**正确行为**。
实测：玩家 x=10 → 相机 10.00；玩家 x=27 → 相机 16.45。跟随与边界钳制都正常。
**以后看到「相机与玩家 X 差很多」，先算 `minX/maxX` 再下结论。**

## 6. DSH（DeepSeek Harness）接入 Unity MCP —— 环境记录

> 本轮会话是在 **DSH** 而非 WorkBuddy 下完成的，MCP 接入方式与旧文档记录不同，**下一次换环境时照这里配**。

### 6.1 配置位置

DSH 不读 `.mcp.json`，而是读 profile 的 cordis patch：

```
C:\Users\<用户>\.dsh\profiles\desktop\cordis.patch.yml
```

（当前生效 profile 路径以环境变量 `DSH_PROFILE_DIR` 为准。）

### 6.2 正确的条目写法（**必须用 `insert:`**）

```yaml
- insert:
    - id: mcp-unity
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: unityMCP
        transport: stdio
        command: C:/uv-mcp/uvx.exe
        args:
          - --offline
          - --from
          - mcpforunityserver==10.3.0
          - mcp-for-unity
          - --transport
          - stdio
        toolCallTimeoutMs: 180000
```

### 6.3 三个致命坑

1. **新条目必须包在 `- insert:` 下**。直接写 `- id: xxx` 只会去覆盖同 id 的已有行，找不到就**静默忽略**，重启后毫无反应（本轮踩过）。
2. **profile 只在 DSH 启动时读取**，改完必须**完全退出 DSH 再重新打开**，没有热加载。
3. `toolCallTimeoutMs` 默认 60 秒，Unity 切场景/编译容易超时，建议调到 180000。

### 6.4 验证接入是否真的通了

```powershell
# 确认进程是 DSH 拉起的（父进程应是 DeepSeek Harness.exe）
Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'mcp-for-unity' } |
  Select-Object ProcessId, Name, CreationDate
```

工具注册后模型侧应看到 `mcp__unityMCP__*` 一整套工具，并可用 `manage_scene(action="get_active")` 读到当前场景。

### 6.5 Unity 侧版本

`BiShe/Packages/MCPForUnity/` 是**嵌入式包**，`com.coplaydev.unity-mcp` 版本 **10.3.0**，与服务端 `mcpforunityserver==10.3.0` 版本一致（旧交接文档写的 10.2.0 已过时）。

## 7. 本轮踩到的其它环境坑

1. **PowerShell 改写含中文的 .cs 文件会写坏**：用 `Set-Content`/`-replace` 处理 UTF-8 中文源码时出现乱码 + 换行丢失，导致 9 条编译错误。**改中文源码一律用编辑工具的字符级替换，不要用 shell 管道重写整个文件。**
2. **执行策略禁止直接跑 .ps1**：`& script.ps1` 报 `UnauthorizedAccess`，改用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File script.ps1`。
3. **`pwsh` 命令不在 PATH**，只有 Windows PowerShell 5.1 可用。
4. `execute_code` 的 Roslyn 编译器下：`Object` 有歧义（写 `UnityEngine.Object`）、`Material` 没有 `sharedMaterial` 属性。
5. `read_console` 的 `format` 参数只接受 `plain` / `detailed` / `json`（传 `true` 会校验失败）。
6. **截取运行时表现时的方法学**：截图前先把 `Time.timeScale` 降到 0.01~0.02 并临时用反射拉长动画时长，否则截图 API 的异步延迟会让特效已经结束；截图后**务必复位 `timeScale = 1`**。
