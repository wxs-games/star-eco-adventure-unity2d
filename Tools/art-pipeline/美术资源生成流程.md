# 美术资源批量生成流程（用一次读一次）

> **给 AI 的说明**：当用户要求"批量生成/补齐美术资源"时，先完整读一遍本文件，按流程执行；平时对话不需要读本文件。
> **给用户的说明**：以后新开批次资源，直接对 AI 说这句话即可——
> 「读 Tools/art-pipeline/美术资源生成流程.md，按排期表'未开始'条目继续生成，风格按 README 基准，完成后回写排期表并输出对齐报告」

（路径以工程根为基准：`Tools\art-pipeline\` 位于 Unity 工程文件夹内、与 `Assets` 并列。）

## 一、三份核心文件的分工

| 文件 | 角色 | 何时用 |
|---|---|---|
| `GraduationProject/Art/2D游戏动画资源排期表.xlsx` | **生成工单**：Clip 名、帧数、Samples、循环、事件帧、制作状态。实测含 4 个 sheet：`进度看板` / `主角动作清单` / `敌人与BOSS` / `资源规范` | 规划期填条目；执行期 AI 按"未开始"条目干活、完成后回写"已完成" |
| `Assets/Art/README_素材说明.md` | **风格基准**：画风、各角色 cell/身高/localScale、Unity 导入设置 | 生成与处理素材时全程对照，保证新素材与旧素材风格统一 |
| 本文件 | **操作手册**：流程步骤、脚本用法、复用指令 | 每批次开工时读一次 |

## 二、标准流程（6 步）

1. **测基准**：用脚本测量既有精灵表（cell 尺寸、条内最高帧身高、底留白、水平居中），得到量化基准。已有基准速查见下方"基准速查"。
2. **生成 raw**：按排期表条目逐条生成网格精灵表（prompt 要素见"四"），**优先透明底**，存到 `Art\Art\<角色>\Sheets\raw\<名>_raw.png`。白底/黑底素材也可用，管线会在入口先抠成透明（见步骤 3）。
3. **处理落盘**：跑 `process_sheets.py` → 入口按背景类型归一化（透明底直通 / 白底·黑底先抠图）为统一透明 RGBA master → 自动切格 → 连通域清理（去碎影，可只留最大域）→ 以条内**最高帧**为基准统一缩放到目标身高（画格宽度亦以**最宽帧**自适应，防止挥砍等横向大动作被裁）→ 脚底基线对齐（底留白 7px）+ 水平居中 → 重拼等大透明精灵表，同时输出 `Sheets\<名>_sheet.png` + `Frames\<名>\<名>_NN.png`。全程只处理 alpha，不再经过白底中间图。
4. **目检**：先跑 `check_frames.py` 做逐帧尺寸比对（画布是否等大、身高/脚底是否一致、与待机相比是否偏矮、有无内容触边），再 Read 成品 sheet 检查抠像干净、帧朝向统一朝右、动作姿态正确；不合格的重生成（如朝向单一帧错，可直接翻转变换修复，不必重新生成）。
5. **回写排期表**：状态改"已完成"、画布尺寸改真实 cell、精灵表路径核对；`README_素材说明.md` 同步新增动作行与帧数合计。
6. **验证 + 报告**：Unity 刷新资产、控制台 0 error；按 AGENTS.md 协议输出需求对齐报告。

## 四、生成 prompt 要素（SDXL 口径）

- 开头声明用途与网格：`[Game sprite sheet, CxR grid, N frames on pure white background]`
- 逐帧动作分解（(1)…(N)），保证帧序列可读
- 角色特征全部列出（帽子/马甲/背包/机械爪等），句尾加 `consistent character design across all frames`
- 统一朝右 `always facing right`；机械单位加 `painterly cel shading, weathered rusty metal`
- 结尾：`no text, no grid lines, pure white background, each frame fully contained in its cell`
- 尺寸限制：总像素 ≥ 3,686,400（如 2560×2560、3456×2304）；输出可能是 .jpg，处理脚本自动转 .png

## 五、处理脚本（与本文件同目录）

> 目录内共 **29 个脚本**（27 个 `.py` + 2 个 `.mjs`）。下表按职能分组，**每个脚本都在表内**，不存在「目录里有、文档没写」的脚本。

### 5.1 主链路（日常生成素材用这一组就够）

| 脚本 | 用途 |
|---|---|
| `auto_pipeline.py` | **一条命令走完全流程**：识别一张 raw 属于「一图单动作」还是「一图多动作」→ 自动选模式 → 处理 → 自检。用法 `python auto_pipeline.py Player [--scan] [--only 动作名] [--vision]`；`--scan` 只判定不动文件，`--vision` 在未登记/多动作时额外跑识图复核 |
| `gen_sheet.mjs` | 生成端：经 codex-image-router 插件批量出「网格精灵表 raw 图」。用法 `node gen_sheet.mjs Player [--only Idle Run] [--size 1536x1024] [--quality high] [--force] [--layout multi]`。产物 `Assets/Art/Art/<角色>/Sheets/raw/<角色>_<动作>_raw.png`（白底、等大网格） |
| `process_sheets.py` | 核心：入口归一化→切格→连通域清理→统一缩放→基线对齐→重拼，落盘 Frames+Sheets；SPECS 表内新增条目需写 name/cols/rows/n/cell/target_h；缩放基准与画格宽均取条内**最大帧**（最高/最宽），保证任意帧不被裁，ref='median' 可按中位数缩放（仅帧高完全一致时用）；可选 `norm='frame'` 逐帧身高归一（各帧先等比缩放到条内基准身高再统一缩放，用于源素材帧间人物大小不一致，如 Attack01）；可选 `anchor='base'` 底座锚点（按脚底/底座中心定位，避免横向特效拉宽包围盒导致人物横移） |
| `detect_layout.py` | 布局识别：判断一张 raw 是「一图单动作(多帧)」「一图多动作」还是「一图单帧」。几何层（确定性，不花钱）按 alpha 投影推网格 cols×rows、每格是否有主体、算相邻帧剪影差异曲线；语义层（识图模型）把图交给多模态模型直接问「几个动作、每段第几帧到第几帧」 |
| `check_frames.py` | 逐帧尺寸比对（通用校验）：对 `Frames/<Clip>/` 逐帧输出画布、主体身高、脚底线/底留白、底座水平偏移、内容左右留白，并做判定——结构问题（画布不等大、空帧）直接 FAIL；身高极差、与参考动作（默认 `Player_Idle`）的身高差、内容触边等只 WARN，加 `--strict` 才当失败。用法：`python check_frames.py [Clip…] [--ref 参考Clip] [--dir 任意帧目录 --ref-dir 参考目录]`，退出码 1 表示有 FAIL |
| `verify_raw_grid.py` | 校验网格 raw **每格人物是否贴边/越界**：按 `cols × rows` 均分切格，逐格算前景包围盒到四边距离，`≤ 2 px` 判为贴边（切图会缺一块）。用法 `python verify_raw_grid.py`（默认扫 Player 全部 raw，网格规格取自脚本内 `GRID` 表）或 `python verify_raw_grid.py Player_Boss01` 指定若干条；退出码 1 = 存在贴边帧。**切图前必跑，要求输出「贴边帧 = 0」**；贴边只重试或换网格（少数列×多行 / 加大画布），不要改切分尺寸 |
| `measure_base.py` | 测量现有精灵表基准：每格内容 bbox、角色高度中位数、脚底留白，用于新素材对齐 |
| `make_preview.py` | **通用**动作总览预览图（深绿底）：默认自动扫描 `Assets/Art/Art/**/Frames/*` 下的全部动作（需要同名 `Sheets/<名>_sheet.png`），按固定帧高逐行拼图，存 `Assets/Art/_预览/contact_sheets.png`；`--clips 名1 名2` 只拼指定动作，`--out` 改输出路径，`--frame-h` 改帧高（默认 110）。累计动作多时建议图像高度过大前先调小 `--frame-h` |

### 5.2 前处理（把不合规的源图变成可切图的 raw）

| 脚本 | 用途 |
|---|---|
| `compose_sheet.py` | **新流程入口**：单帧序列 → 均匀网格 raw（喂给既有 `process_sheets.py`）。老管线输入是「一张已排好帧的网格图」，但出图范式已改成**逐帧独立生成**（整网格文生图控不住每帧姿态，7/8 帧会同姿势），产出是 N 张各不相同的单帧，必须先合成网格才能进老管线 |
| `prepare_grid_sheet.py` | 白底网格精灵表 → 可切图的透明网格表，解决三件事：①白底转真透明（反预乘去白边，边缘色用最近实心像素回填，否则放大后发黑发白）②抹掉模型画的格子边框（每格按 inset 内缩后再取）③按连通域面积过滤水印杂点（只保留主体） |
| `preprocess_irregular_raw.py` | **通用**不规则图集预处理：透明底直通 → 连通域分帧（按 y 最大间隙分行，行内按 x 排序）→ 只取主体包围盒 → 颜色外溢 → 重拼规则网格 raw（画格宽高按条内最大帧，直贴保留 straight alpha）。用于源图不是等大网格、需要先转成规则 raw 再进 `process_sheets.py` 的场合。用法：`python preprocess_irregular_raw.py --src 源图.png --out Assets/Art/Art/<角色>/Sheets/raw/<名>_raw.png --n 9 --cols 3 --rows 3 --src-rows 2 --min-h 120`，先加 `--dry-run` 看分行/帧数/画格尺寸，确认无误再落盘；`--area-min 500` 过滤碎点，`--min-h` 用于把浮在角色外的分离特效排除在角色帧之外 |
| `preprocess_attack01_raw.py` | Attack01 **不规则图集** → 连通域自动分帧 → 重拼规则 4×2 透明底网格 → `raw/Player_Attack01_raw.png`。用户交付的 1536×1024 / 8 帧图集人物与光效跨格排布，硬按格线切会把人切断，故先按连通域取 8 个角色再按 (行,列) 排序重排 |
| `preprocess_attack03_raw.py` | Attack03（投掷蓝水桶）**不规则图集**预处理：透明底 → 连通域分帧（9 个角色，5+4 两行）→ 重拼规则 3×3 → `raw/Player_Attack03_raw.png`。图集中的飞桶等分离特效靠 `--min-h` 排除在角色帧之外 |
| `preprocess_run_raw.py` | Run 类素材预处理的**固定示例**（5+3 排布 → 4×2，8 帧，写死源路径），仅作 alpha 直通写法的参考；新素材一律改用上面的 `preprocess_irregular_raw.py` |
| `slice_actions.py` | 多动作合图按 `layout.json` 切成**分动作 raw**，补上「一个 raw = 一个动作」这条前提。纯裁剪：不缩放、不居中、不抠图，像素原样搬。用法 `python slice_actions.py --src 大图.png --layout layout.json [--dry-run] [--out 目录]`；layout 用 1 基闭区间 `row0/row1 × col0/col1` 描述每个动作占的**整格块**，所以切出来是动作列数×行数 个完整格，帧不会被切断；归一化仍由 `process_sheets.py` 按动作独立计算 |

### 5.3 后处理与修复（已落盘素材的补救）

| 脚本 | 用途 |
|---|---|
| `upscale_sheet.py` | 精灵表**无损超分**（Real-ESRGAN anime 4x）后按工程规格重排。不是重画：RGB 走超分模型，alpha 单独双三次放大后收紧边缘，透明区 RGB 先用最近邻不透明像素外扩填色（否则放大后边缘发黑）；**全部帧共用同一套变换**（同缩放、同落点），帧间相对位移原样保留。用法 `python upscale_sheet.py --src sheet.png --cols 5 --rows 3 --canvas 1200x833 --baseline 825 --height 755 --outdir out [--scale 4] [--device cpu] [--align shared\|per-frame\|top]`；权重默认取同目录 `weights/RealESRGAN_x4plus_anime_6B.pth`，需 torch |
| `redraw_sprite.py` | 把平涂精灵表按「**矢量式重绘**」放大——不是像素插值，而是重新描边重新填色。超分模型是「根据低分辨率像素猜高分辨率像素」，边缘必然是插值过渡灰、线条发虚、平涂区带噪；对本来就很小的平涂动画原画一眼就是「被拉大的图」。本脚本三步全部基于原图真实信息（归一化色板 → 重描轮廓 → 重填色），不凭空生成内容 |
| `feather_smoke.py` | 对**已生成**的精灵帧与精灵表批量补**顶部羽化**（一次性后处理，可重复执行）。文生图常把烟柱/蒸汽画到格子上沿就截断，成品顶部是硬平口——缩放补不回丢失的像素，只能把切口做成渐隐。管线内可在 spec 加 `feather_top=True`；素材已导入 Unity、不想重跑整条管线时用本脚本单独补一次 |
| `fix_victory.py` | 单帧水平翻转修复朝向的示例（可复制改路径复用） |
| `derive_sets_from_lockup.py` | **定妆图派生（通用版）**：以「某一帧」为**像素基准**派生同一角色的其它动作套。当定妆图被指定成「某个动作的某一帧」（如炮塔射击第一帧）时，其余动作的同一部件必须与它**像素级完全一致**——文生图做不到，`process_sheets.py` 的生成式管线同样做不到（每帧都会重画）。脚本改以该帧为底图、**逐帧只在背景区叠加效果**，并用硬约束保证一致性（不是靠人眼检查）。用法 `python derive_sets_from_lockup.py [--only 套名…]`；换角色改脚本头部 `CHAR_DIR` / `BASE_REL`（定妆帧），派生哪几套改 `SETS`（每套写 cols + effect + 逐帧 plan）。**当前内置任务 = Tower01**（定妆帧 `Tower01_Fire_00`，派生 `Tower01_Idle` 警戒灯脉动 / `Tower01_Aim` 炮口蓄能 / `Tower01_Disable` 去饱和变灰+升烟），画格 1039×979、塔体像素零位移、输出沿用原名与原帧数故 `.anim` 引用不失效 |
| `make_breakables.py` | 可破坏物（道具/障碍）素材处理：**洋红键控 + Voronoi 碎裂**。输入洋红底（`#FF00FF`）单主体原图，输出「整块」+「若干碎块」两套透明底 PNG，并写好 Unity 导入用的 `.meta`。要点：只动 alpha 不做白底往返（边缘不出白圈）、despill 压掉边缘品红溢出（否则缩放后一圈粉边） |
| `sandbox_process.py` | 在**沙箱副本**里跑 `process_sheets.py`，绝不触碰工程 Assets。原理：`process_sheets.py` 按 `dirname(__file__)/../../Assets/Art/Art` 定位 ROOT，把副本放进 `<sandbox>/Tools/art-pipeline/` 后 ROOT 自动指向沙箱内的 Assets；再把 SPECS 换成单条目，就只处理本次新动作。用法 `python sandbox_process.py --sheet raw.png --name Player_Run12 --cols 4 --rows 2 --cell 300x600 --sandbox D:\tmp\sb [--target 760] [--white-clean]`。适合「先看结果再决定是否落盘」的试跑 |

### 5.4 生成式补充与 2D 骨骼（造新姿态 / 新角色骨架时用）

| 脚本 | 用途 |
|---|---|
| `gen_from_ref.mjs` | 用「**指定参考图**」+「提示词文件」出一张网格 raw 图（走 codex-image-router）。与 `gen_sheet.mjs` 的区别：gen_sheet 的参考图固定是角色定妆图，本脚本允许把任意一张图（外部半成品、旧素材、别人的图）当参考图重绘，用于「沿用某张图的构图/姿势，但提高分辨率 + 修正错误」。用法 `node gen_from_ref.mjs --ref <参考图> --prompt <提示词txt> --out <输出png> --size 3072x3072 [--quality low\|medium\|high] [--force] [--dry]` |
| `inpaint_limbs.py` | **局部重绘**：把定妆图的躯干像素级保留，只让 AI 重画四肢。全局 img2img 的 denoise 是「整张图一个旋钮」：≤0.55 姿态不动，≥0.80 脸和衣服被重画成模型心里的「通用卡通男孩」。局部重绘把旋钮作用范围限制在 mask 内、mask 外像素最后强制贴回 |
| `run_cycle.py` | 批量出「局部重绘」循环动画帧。上部躯干永远取自定妆图（像素级），只有 mask 内的腿由 AI 逐帧重画，每帧给不同 seed + 跑步相位描述 → 拿到 12 个互不相同的腿部姿态 |
| `rig_cut.py` | **2D 骨骼绑定第一步**：把定妆图按关节拆成可独立旋转的部件，不做任何重绘、角色像素原样切开。两个关键技术点：①切分靠「颜色 + 连通域」而非矩形（侧视图里手垂在大腿旁，手臂与腿的矩形范围重叠，矩形切会把腿切成手臂）②每个部件在关节处补一个「填充圆盘」（绕自身圆心旋转时圆盘形状不变，肢体大幅摆动时关节处不露透明洞） |
| `rig_render.py` | **2D 骨骼绑定第二步**：用切好的部件 + 骨骼角度渲染逐帧动画。角色像素 100% 来自定妆图、不做任何生成/重绘 → 帧间绝对稳定、不会闪烁。**角度约定（关键，别搞反）**：正值 = 该肢体末端朝「角色面向的方向（右/前方）」摆动；thigh 正值 = 大腿前摆，shin 负值 = 膝盖弯曲（小腿向后折），arm_u 正值 = 上臂前摆，arm_f 正值 = 前臂相对上臂向前弯 |
| `rig_side.py` | 侧视图 cutout 骨骼 **v2**：修掉 v1「腿像被硬掰开」的根因。①v1 两条腿共用同一髋点（落在裆部正中间，实测近腿真实髋 x≈843、远腿 x≈650，差近 200px）→ 绕裆部中点转就是「从胯中间张开」，正是掰腿感来源；v2 改为两腿各有独立髋/膝/踝 ②膝角用 `max(0, sin(...))` 导致半个周期恒为 0 → 膝盖完全伸直，v2 修正 |

## 七、两种模式：一图一动作 / 一图多动作

生成端（`gen_sheet.mjs`）：

| 模式 | 命令 | 产物 |
|---|---|---|
| 一图一动作（默认） | `node gen_sheet.mjs Player --only Attack02` | `Player_Attack02_raw.png`（4x2 = 8 帧） |
| 一图多动作 | `node gen_sheet.mjs Player --layout multi --only Attack01 Attack02` | `Player_Attack01+Attack02_raw.png`（8 列 x 2 行，一行一个动作，1536x3072 时每格 384x768，与单动作同密度） |

`--layout multi` 的约束：所选动作**帧数必须一致**（一行放一个动作，列数=帧数）；
画布按每格 384x768 自动算，超过 3840 单边上限会压缩并告警。

处理端（一条命令）：

```
python auto_pipeline.py Player                # 判定 + 选模式 + 处理 + 自检
python auto_pipeline.py Player --scan         # 只看判定，不动文件
python auto_pipeline.py Player --only Attack01+Attack02
python auto_pipeline.py Player --vision       # 未登记/多动作时额外跑识图复核
```

判定优先级：

1. 文件名含 `+` → 多动作，按行带均分；
2. 名字在 `SPECS` 注册表 → 单动作（**注册表优先，不让识图改已登记动作**：
   实测识图会把一套连招的第二段也算成一个动作，照它切会把一个 Clip 劈成两个）；
3. 都没命中 → `detect_layout.py` 识图判定。

手工/其他来源的合图：

```
python slice_actions.py --src 大图.png --layout layout.json     # 可加 --dry-run
```

layout.json 里每个动作写 `name + row0/row1 + col0/col1`（1 基闭区间），脚本会校验越界、
重叠和空格子；切完直接 `python process_sheets.py <动作名...>` 即可。

`detect_layout.py` 说明：

- 几何层：按 alpha（或白底抠出的掩码）投影推网格，统计每格是否有主体，算相邻帧剪影差异曲线；
- 语义层：把图发给多模态模型问「有几个动作、每段第几帧到第几帧」；
- **调 gateway 的 `max_tokens` 必须 ≥ 12000**：该模型把思考过程也算进 completion，
  给小了只会返回 `reasoning_content`，`content` 是空的（踩过这个坑）。
