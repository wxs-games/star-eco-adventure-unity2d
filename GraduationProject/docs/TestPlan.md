# 《星际环保》测试与验收计划 · Test Plan

> 版本：v1.0 | 最后更新：2026-10-30
> 岗位归属：**主程序 / QA** 撰写并执行；每个功能完成后由提交者自测并签字
> 上游约束：`TDD.md`（技术方案）、`specs/*/requirements.md`（逐功能验收条件）
> 数据来源：`PlayerConfig.asset`、`LevelConfig*.asset`、`EcoConfig.asset`、代码常量（预期值全部为实测配置值，不是估计值）

---

## 一、测试范围与原则

### 1.1 范围

| 在范围内 | 不在范围内 |
|---|---|
| 三关完整流程可通关 | 多平台兼容（只测 Windows） |
| 三关所有机关按设计生效 | 32:9 / 4:3 等非 16:9 分辨率 |
| 战斗、受击、死亡、净化 | 多人联机（无此功能） |
| 全部 UI 界面的打开/关闭/输入冻结 | 本地化（只有简中） |
| 存档读写与关卡解锁 | 反作弊 |
| 音频播放与音量设置 | — |
| 性能：Build 版 GC = 0 | 内存峰值、发热 |

### 1.2 原则

1. **预期值必须来自配置文件或代码常量**，不许写"应该差不多"。本文档每条的预期值都附了出处。
2. **判定标准是"玩家能不能感知"**，不是"代码逻辑对不对"。例如握持误差 15.6 sprite px ≈ 屏幕 3.3px，肉眼不可见即通过。
3. **只在 Build 版下判定性能与最终观感**。Editor 下的数字不作为发布口径。

## 二、测试分层

| 层级 | 手段 | 覆盖 | 频率 |
|---|---|---|---|
| **L1 单元测试** | `Assets/Tests/EditMode/CoreLogicTests.cs`（NUnit，Unity Test Runner） | `Core` 层纯算法：伤害公式、数值保护、CSV 解析 | 每次改 `Core` |
| **L2 集成自测** | Editor Play 模式，代码注入 + 反射 | 状态机转移、事件链、UI 面板栈 | 每个功能完成时 |
| **L3 冒烟测试** | 人工从头玩一遍三关 | 全流程可通关 | 每次合并到大版本 |
| **L4 回归测试** | 按 §5 清单逐条过 | 历史缺陷不复发 | 每次发版前 |

> **注意 L2 的边界**：Play 模式下的输入注入**驱动不了** `Update` 里的状态转移（`ReadInput` 会覆盖注入值）。要测 Idle→Run 这类转移，必须用真实键盘，或反射改字段并同时禁用冲突组件。

## 五、回归清单（每次发版前必过）

按顺序走，任何一条失败即阻塞发布：

- [ ] 从主菜单 → 第一关 → 通关 → 第二关 → 通关 → 第三关 → 击败 Boss → 看落幕对白 → 结算 → 回主菜单（**全流程无卡死**）

- [ ] 图鉴能打开，收集数正确
- [ ] 选关界面三关初始状态正确（已通关的有星级）
- [ ] 设置里改音量后，重启游戏仍保留
- [ ] 暂停 → 继续 → 暂停 → 回标题，反复 3 次无异常
- [ ] 知识卡 8 张全部可拾取
- [ ] 第二关 5 个叙事点（艾娃/提示牌/3 张卡）全部可交互
- [ ] 第三关 2 张知识卡可拾取
- [ ] 碎裂平台、移动平台、水位谜题、拉杆各测一次
- [ ] Build 版 Profiler 确认 GC = 0
