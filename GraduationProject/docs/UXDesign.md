## 1. 输入方案

### 1.1 键位全表（实测自代码，非设计稿）

| 操作 | 键位（键盘） | 代码依据 | 备注 |
|---|---|---|---|
| 左右移动 | `A`/`D` 或 `←`/`→` | `Input.GetAxisRaw("Horizontal")` | Unity 默认 InputManager 轴 |
| 跳跃（可变高） | `Space` | `Input.GetButtonDown("Jump")` | 上升中松键 = 短跳（`JumpCutMultiplier`） |
| 上下（爬梯/看方向） | `W`/`S` 或 `↑`/`↓` | `Input.GetKey(W/UpArrow)` | 取按住状态，非事件 |
| 攻击（夹钳三段） | **`J`** 或 左 `Ctrl` | `Fire1` 或 `KeyCode.J` | 见 §1.2 冲突 |
| 喷洒净化（按住） | `K` | `KeyCode.K` | 移速降至 30% |
| 蓄力净化波（长按 0.8s 松开） | `L` | `KeyCode.L` | 消耗 25 净化剂 |
| 闪避翻滚 | 左 `Shift` | `KeyCode.LeftShift` | 有无敌帧 |
| 冲刺 | **左 `Ctrl`** | `KeyCode.LeftControl` | 无无敌、可空中一次 |
| 互动（对话/提示牌/解救/拉杆） | `E` | `KeyCode.E`（各触发器各自读） | 统一语义，见 §3 |
| 推进对话 / 补完整句 | `E` | `DialoguePanel` | 同一颗键三态 |
| 暂停 / 关栈顶面板 | `Esc` | `UIManager.HandleEscape` | 栈空才开暂停 |

**没有手柄支持，没有触屏支持，没有按键重映射。** 这是范围收敛，不是遗漏（见 §7）。

### 1.2 键位冲突登记（必须知道的两条）

| # | 冲突 | 后果 | 处理 |
|---|---|---|---|
| **K1** | **左 `Ctrl` 同时是「攻击（Fire1）」和「冲刺」** | 按一下会**同时**触发攻击与冲刺，FSM 谁先转移谁赢，表现为"按 Ctrl 有时砍、有时冲" | ⚠️ **未修**。当前玩家实际都用 `J` 攻击，所以没人报障。若要做正式发布：把冲刺改 `Shift`+方向、或把 `Fire1` 从 InputManager 里的 `left ctrl` 摘掉（P1，登记于 `RiskRegister.md` U-03） |
| K2 | 左 `Shift` = 闪避；`Fire3` 也绑左 `Shift` | 目前 `Fire3` 无任何代码读取，**无实际影响** | 保留，记录在案 |

### 1.3 输入闸门（为什么"按键没反应"有时是正常的）

```text
Input.GetKey(...) → 被三处闸门拦下：
  ① PlayerController.InputLocked        面板阻断（UIManager.ApplyInputLock 写）
  ② PlayerController.ExternalInputLock  外部强制锁（同上，第二层）
  ③ SprayController.inputAllowed        额外判 UIManager.IsBlocking
交互类（E 键）：各触发器自己判 UIManager.IsBlocking
```

**只有 UI 层能解除**：`InputLocked` 会被玩家 FSM 的 `Exit` 清成 false（翻滚/冲刺/受击都会），所以必须有 `ExternalInputLock` 这第二层。这是踩过的坑（`specs/07` §2.2）。

### 2.2 面板规格表

| 面板 | 进入方式 | 退出方式 | 冻结输入 | 冻结时间 | 默认按钮 |
|---|---|---|---|---|---|
| 主菜单 | 启动 / 返回主菜单 | 进入关卡 / 退出 | 是 | — | 开始新游戏 |
| 关卡选择 | 主菜单「关卡选择」 | 返回 / Esc | 是 | — | 第 1 关 |
| 环保图鉴 | 主菜单「环保图鉴」 | 返回 / Esc | 是 | — | 返回 |
| 设置 | 主菜单或暂停菜单 | 返回 / Esc | 是 | — | 返回 |
| **HUD** | 关卡自动 | 随场景销毁 | **否** | 否 | — |
| 暂停菜单 | Esc（栈空且 Playing） | 继续 / Esc | 是 | **是**（`timeScale=0`） | 继续游戏 |
| 对话 | 走近 NPC 按 E / 关卡落幕 | 末句按 E / Esc | 是 | 否 | — |

**只有暂停冻结 `Time.timeScale`**：对话不冻结时间，因为背景世界要继续呼吸（敌人动画、水流、BGM），冻结会让对话像"卡住"。

### 2.3 层级原则（谁盖谁）

```text
结算面板 (100)        ← 最高（一出现就压住一切）
  ↑
Boss 演出 (90)
  ↑
提示牌 (80)
  ↑
对话面板 (70)
  ↑
设置 / 图鉴 / 关卡选择 (60)
  ↑
暂停菜单 (50)
  ↑
Toast 提示条 (45)
  ↑
Boss 血条 (40)
  ↑
伤害数字 (36)
  ↑
敌人血条 (35)
  ↑
主菜单 (20)
  ↑
HUD (10)              ← 最低（常驻，不参与 Esc）
```

`UIManager` 用**栈**实现：后开的一定在前开的上面；`Esc` 永远关栈顶（HUD 除外，因为它 `BlocksInput=false`）。

> **⚠️ 2026-10-31 按实测校正**：原图把「设置 / 图鉴 / 关卡选择」画在「对话面板」之上，与实际相反。
> 实际 `sortingOrder`：Result **100** > Boss 演出 **90** > Signboard **80** > Dialogue **70** > 设置/图鉴/关卡选择 **60** > Pause **50** > Toast **45** > Boss 血条 **40** > 伤害数字 **36** > 敌血条 **35** > MainMenu **20** > HUD **10**。
> **设计含义**：对话面板比设置/图鉴**高**——对话是剧情推进的强提示，不该被暂停类面板压住；而 Toast（45）低于设置（60），意味着**面板打开时 Toast 会被遮住**，这正是「面板独占画面」的预期行为。

## 3. 统一互动范式（E 键）

全项目 **4 类互动共用一颗 E 键**，共享同一套交互模型：

| 互动 | 组件 | 半径 | 气泡文案 | 触发后 |
|---|---|---|---|---|
| NPC 对话 | `DialogueTrigger` | 2.6u | 按 E 交谈 | 打开对话面板 |
| 提示牌阅读 | `SignboardTrigger` | 2.6u | 按 E 阅读 | 打开分页阅读面板 |
| 解救动物 | `RescueTarget` | 2.2u | 按 E 解救 | 播 Interact → 0.3s 开笼 |
| 拉杆 | `LeverSwitch` | ~2u | 按 E 扳动 | 拨动机关 |

**共同规则（4 条，新加互动必须遵守）**：

1. **半径检测不用物理 Trigger**：`Vector2.Distance` 判定，避免与净化判定盒/攻击判定盒互相触发。
2. **气泡是世界空间 Canvas**，建在 `Awake`（不是 `OnEnable`，否则编辑器里会形成"隐形白墙"），`localScale=0.01` 做像素→世界换算。
3. **`UIManager.IsBlocking` 为真时不可互动**：面板开着按 E 不会被下层触发器吃走。
4. **⚠️ 摆放铁律：同类互动点中心间距 ≥ 4.8u**（= 2.6 + 2.2）。因为每个触发器都在自己的 `Update` 里读 `Input.GetKeyDown(E)`，**没有互斥机制**——半径重叠就会一键两用。`Ava_Forest` 从 −23.8 移到 −27.4 就是因为与笼子（−22）重叠。

#### 4.2.1 净化剂拾取提示规范（U-03 · 2026-10-31 确认）

> **背景**：用户回归反馈「路上的小点点可以捡但没什么作用」。根因是：净化剂补给瓶被捡起时，HUD 左上蓝色净化剂条会跳一下，**但瓶子接近满时数值看不出变化**，玩家感知为零。补一条显式提示即可解决，不需要恢复任何数值面板。
> 需求来源：`RiskRegister.md` U-03（已发生 / 影响低 / 纯反馈问题）。

**已实现**（`Assets/Scripts/UI/ToastLayer.cs`，B 车道落地，D 车道确认文案与样式口径）：

| 项 | 规格 | 实现位置 |
|---|---|---|
| **文案格式** | `净化剂 +{0}`，`{0}` = **实际回复量**（非请求量） | `ToastLayer._pickupToastFormat` |
| **触发事件** | `PickupCollectedEvent`，且 `Kind == PickupKind.PurifyBottle` | `ToastLayer.OnPickupCollected` |
| **满罐不弹** | `evt.Amount <= 0` 时**静默跳过**，不弹「+0」 | 同上 |
| **颜色** | 净化主题蓝 `RGB(0.35, 0.75, 1.0)`，与 `HUDController.TankFillColor` 同值 | `ToastLayer.PurifyTint` |
| **字号** | 34（`CanvasScaler` 按 1920×1080 缩放） | `ToastLayer._fontSize` |
| **位置** | 屏幕底部上方 190px，水平居中 | `ToastLayer._bottomOffset` |
| **时长** | 停留 1.7s，淡入 0.15s，淡出 0.4s | `ToastLayer._displaySeconds/_fadeIn/_fadeOut` |
| **排队** | 上限 4 条，超出丢弃新消息（防积压） | `ToastLayer._maxQueue` |
| **结算期抑制** | 关卡通关/失败时清队列并收起，避免与结算按钮重叠 | `ToastLayer.Suppress()` |

**两条设计约束（写下来防止后续被改坏）**：

1. **弹「实际回复量」而非「请求量」**。`PurifyPickup` 用 `tank.Restore(requested)` 的返回值（真实增量）广播，而非 `requested`（请求量）。罐子已满时真实增量是 0，此时**不弹提示**——弹「净化剂 +20」会与 HUD 的实际数值矛盾，是**反馈失真**。
2. **不复用「+0」占位**。玩家捡了东西却什么都没发生，比不捡更困惑。

> **文案属策划域**：`ToastLayer._pickupToastFormat` 是 Inspector 可改的序列化字段，策划改文案**不需要改代码**。若日后要改（如改成「净化剂 +20（已满）」），在本节更新口径即可。

**罐已满时的处理（2026-10-31 策划裁决）**：

| 分支 | 表现 | 依据 |
|---|---|---|
| 罐未满 | 弹「净化剂 +{实际回复量}」（蓝） | U-03 已实现并实测通过 |
| **罐已满** | **不弹任何提示**；瓶子**留在原地不消失**（策划裁决：让玩家看见「瓶子还在、罐子没动」= 世界内自解释反馈） | `LevelDesign.md` §5.8.2 裁决 ② / §5.8.3 |

> **不给「净化剂已满」文案的刻意选择**：罐满不是错误状态（本作无资源见底惩罚，HP 归零才失败），给一句只描述失败的话会让玩家误以为漏了什么；且 HUD 已刻意「不显示数值」，一味加提示与该取向相悖。若用户另有决定，备选文案是「净化剂已满」。

**同类反馈的对照**（知识卡，**已落地**）：

> 知识卡拾取走 `KnowledgeCardPickup.cs`：**`Pickup` 音效 + Toast「获得知识卡：{卡片标题}」**（`UIUtility.AccentGreen` 绿色，与净化剂的蓝色区分）+ 卡片精灵隐藏。图鉴解锁由 `CodexService.CollectCard()` 直连，**不经事件总线**。
> 它与净化剂提示的差别只在**颜色语义**（绿=知识 / 蓝=资源）与**文案主体**（「获得知识卡：X」而非「+20」），机制完全同构——**新增同类拾取物时照此复制即可**。

#### 4.2.2 拾取的触发范围规则（2026-10-31 策划裁决 · 主程序提请）

> **来源**：主程序实测拾取物时发现——玩家的 `SprayHitbox`（trigger 1.4×1.2，局部 x=**+1.37**）与 `AttackHitbox`（trigger 2.4×1.5，局部 x=**+0.785**）都是 Player 的**子物体**，
> `GetComponentInParent<PurifyTank>()` 一样能命中 → **玩家只要把喷嘴/攻击范围扫过瓶子，就会把瓶子吸走，不必碰到瓶子本体**。
> 主程序实测该路径**未复现触发**（当时玩家主 collider 处于 disabled 状态），但**逻辑上确实存在**。
> 主程序明确「这属手感/规则范畴，我不擅自改，提请主策划裁决是否算设计意图」——**本节即该裁决。**

**裁决：拾取物必须由「玩家本体」拾取，不接受攻击/喷溅范围触发。这不是 bug，是设计意图。**

**理由**：

| # | 理由 |
|---|---|
| ① | **「捡到」必须等于「碰到」**。玩家看到瓶子消失、罐子跳了一下，却从没走到瓶子跟前——这是**反馈失真**，与 U-03 想解决的正是同一类问题 |
| ② | **量级不合理**。`AttackHitbox` 前伸 0.785u + 半宽 1.2u = 最远触及 **1.99u**；而瓶子 collider 半径 0.45u。**玩家身体离瓶子还有约 1.5u 时，攻击范围就能扫走它**——「隔空吸走」没有任何玩法价值，只会让玩家困惑 |
| ③ | **与「净化」语义冲突**。喷壶是**净化环境**的工具（`GDD.md` §3.1「喷壶只用于净化环境，不对污染生物造成伤害」）。让喷壶顺手捡走补给，等于让「净化」与「拾取」共用一个范围，玩家会分不清自己是在净化还是在捡东西 |
| ④ | **拾取物是稀缺资源入口**（见 `LevelDesign.md` §5.8.2 净化剂经济裁决）。让范围攻击消耗它，等于鼓励玩家「边打边扫」——资源决策被绕过 |

**实现侧要求（主程序）**：

- `PurifyPickup.OnTriggerEnter2D` 的目标判定**必须排除**玩家自身的 `SprayHitbox` / `AttackHitbox`。
  推荐做法：判定时校验命中的 collider **是玩家根节点的 `BoxCollider2D`**（而非任意子 collider），
  或直接排除 `SprayHitbox` / `AttackHitbox` 这两个具体组件。
- ⚠️ **不要用「距离」做兜底**——距离判定在玩家蹲下（`SetCrouch` 改 `box.size`）时行为不稳定，且解决不了「哪个 collider 触发」的根本问题。

**这条规则的适用范围**：**所有拾取物**（净化剂瓶、知识卡），不是只针对净化剂。知识卡目前是 `KnowledgeCardPickup` 独立实现，若它也有子物体触发路径，一并按此规则收紧。

> **顺带澄清一条易混点**：玩家的主 collider 运行时宽度只有 **0.06~0.55u**（蹲下时更窄），
> 这**不影响**触发——拾取物 collider 半径 0.45u，玩家本体从其上方走过时必然重叠（主程序已实测通过：贴地站在瓶子正下方 → 拾取物 count 1→0 被拾取归池 ✅）。

**这次改动的得与失（记录判断依据）**：

- **得**：去掉了"任务清单式"的数值面板，玩家看画面而不是看 UI——污染退去、背景变绿、垃圾变绿植，本身就是最强的进度反馈。也让探索成为玩法。
- **失**：第三关的目标是"清 4 个污染源（含封锁墙）→ 打 Boss"，**没有数字提示时，玩家可能找不到第 4 个**（封锁墙在场地深处）。这是本次改动带来的真实可玩性风险，登记为 `RiskRegister.md` U-05（P1）。
- **补偿方案（未实施）**：目标完成时给一声短促音效 + 场景内一次性粒子；知识卡拾取给 `Pickup` 音效 + 卡面浮起动画。两者都不需要恢复数值面板。

**死因必须区分**：不区分的话，掉出地图的玩家会看到"被击败"，误以为是怪打死的。这是关卡的诚实性原则——**不给玩家错误的因果解释**。

### 4.3 反馈延迟上限（体验红线）

| 操作 | 允许的最大感知延迟 | 现状 |
|---|---|---|
| 按键 → 角色动作 | 1 帧（16.7ms） | ✅ 达标（输入在 `Update` 读，`FixedUpdate` 执行） |
| 攻击 → 命中判定 | 由动画事件帧决定（约 0.19s 的挥击前段） | ✅ 符合"表现窗口=判定窗口" |
| 死亡 → 结算面板 | ≤ 0.5s | ✅ 同帧（L3 例外：Boss 死亡要先播 5.5s 演出） |
| 点按钮 → 音效 | 同帧 | ✅ `UIUtility.PlayClickSfx` |
| 进场景 → 可操作 | ≤ 1 帧 | ✅ `StartLevel` 里 `InputLocked=false` |

## 5. 焦点与按钮顺序

### 5.1 按钮顺序（按"玩家最可能点的"排序）

| 面板 | 顺序 |
|---|---|
| 主菜单 | 开始新游戏 → 继续游戏 → 关卡选择 → 环保图鉴 → 设置 → 退出游戏 |
| 暂停 | 继续游戏 → 重新开始 → 设置 → 返回主菜单 |
| 结算 | 重新开始 → 下一关 → 返回主菜单 |
| 关卡选择 | 第 1 关 → 第 2 关 → 第 3 关 → 返回 |
| 设置 / 图鉴 | 返回（唯一出口，放底部） |

**原则**：破坏性操作（重新开始/退出）**不与"继续"相邻**，且都排在正向操作之后。

### 5.2 焦点与键盘可达性（诚实登记）

- **鼠标可点**，`EventSystem` 缺失时自动创建。
- **纯键盘导航不可用**：所有面板按钮都是 `Button` + `onClick`，但没有配置 `Navigation` 链，也没有默认选中项。所以"只用键盘"无法选择按钮——**必须用鼠标**。
- 这是明确的缺口（§7 G1）。修法：每个面板 `OnOpen` 时 `EventSystem.current.SetSelectedGameObject(首个按钮)` + 设 `Navigation.Mode = Explicit/Automatic`。

## 6. 首次 5 分钟体验路径（Onboarding）

**目标：不读任何文字说明，5 分钟内学会全部核心操作。**

| 时间 | 玩家位置 | 学到什么 | 怎么教的 |
|---|---|---|---|
| 0:00 | 标题界面 | 开始游戏 | 唯一高亮按钮 |
| 0:15 | L1 出生点，Ava 在旁 | 会走路、能对话 | 走进 2.6u 自动出气泡「按 E 交谈」 |
| 0:45 | 第一个垃圾堆前 | 会喷洒（K） | 垃圾堆颜色异常 + Ava 提示「按住 K 净化」 |
| 1:20 | 三个垃圾堆清完 | 净化值 → 100% → 通关 | 背景整体变绿 + 垃圾堆变绿植（无数字面板） |
| 2:00 | L2 左岸两个笼子 | 会解救（E） | 气泡「按 E 解救」+ 动物音效 |
| 2:40 | 河道堵塞 | 喷雾能清障碍 | 与垃圾堆同一操作，零新知识 |
| 3:20 | 木筏通路 | 进度门 | 水位上升的视听提示 |
| 4:00 | 右岸三个污染源 | 会战斗（J） | 敌人先出手，玩家被迫反击 |
| 5:00 | L2 结算 | 星级/评级 | S/A/B/C + ★ |

**教学原则**：
- **一次只教一件事**，且每件事都在"玩家正需要它"的时刻教（不是先讲再练）。
- **新机制复用旧输入**：喷洒（K）在 L1 学，L2 用来清堵塞——不引入新键。
- **没有文字教程、没有弹窗阻断**：所有提示都是场景内的气泡或 NPC 对白。

## 7. 无障碍与缺口（诚实清单）

| # | 缺口 | 影响 | 优先级 |
|---|---|---|---|
| G1 | **无键盘焦点导航**（只能用鼠标点按钮） | 纯键盘玩家无法操作菜单 | P1 |
| G2 | **无手柄支持** | 横版动作游戏的主机手柄习惯无法满足 | P2 |
| G3 | **无按键重映射** | 左手/特殊需求玩家受限 | P2 |
| G4 | **依赖颜色区分状态**（背景色表示污染度、血条红/灰） | 色盲玩家可能读不出污染程度 | P2：HUD 已有百分比数字作为冗余编码（部分缓解） |
| G5 | **无字幕开关**（对白就是文本，无语音） | — | 不需要（本作无配音） |
| G6 | **无闪烁/震动强度选项** | 光敏性癫痫风险（白闪 + 屏幕震动） | P1：`HitFlash` 与 `Shake` 应有强度滑块 |
| G7 | **字号固定**（不随分辨率缩放） | 小屏/低视力阅读困难 | P3：`CanvasScaler` 已按 1920×1080 缩放，实际影响有限 |
| G8 | **无新手引导重看入口** | 教会了但记不住的玩家无处复看 | P2：图鉴里可加"操作说明"页 |
| G9 | **目标完成只闻其声、不见其形**（HUD 目标栏 2026-10-30 移除后，链推进已有 `Pickup` 音效，**但无场景内一次性粒子**） | 玩家不知道"刚做的那件事算不算完成" | P1：补场景内一次性粒子，音效已落地、不需要恢复数值面板 |
| G10 | ~~知识卡拾取零反馈~~ | — | **已关闭**（B2 已落地：`Pickup` 音效 + Toast「获得知识卡：{标题}」，`KnowledgeCardPickup.cs`） |
| G11 | **净化值无数字**（右上角面板 2026-10-30 移除） | 无法精确判断"还差多少"；只能靠画面变绿 | 设计选择（探索向），但对第三关"找第 4 个污染源"不友好，见 `RiskRegister.md` U-05 |

> 这些不是"没想到"，是**明确排期未到**。答辩若被问"无障碍做了什么"，答：有冗余编码（百分比数字 + 音效提示），并在文档中登记了 8 项缺口与优先级——**知道自己缺什么，比假装没有缺口更专业**。

## 8. 一致性检查清单（新增内容上线前必过）

新加任何界面/互动，逐条打勾：

- [ ] 走 `UIManager.Open/Close`，不自己建 Canvas（否则 Esc 关不掉、输入不冻）
- [ ] 阻断型面板设 `BlocksInput = true`；HUD 类设 `false`
- [ ] 面板在 `Awake` 里 `Register`，`OnDestroy` 里 `Unregister`
- [ ] 按钮顺序：正向操作在前，破坏性操作在后，且不相邻
- [ ] 新增互动点与既有互动点间距 ≥ 4.8u（§3 铁律）
- [ ] 世界空间气泡在 `Awake` 建，`localScale = 0.01`
- [ ] 中文字体走 `UIUtility.BuiltinFont`（`NotoSansSC`），不用内置 Arial
- [ ] 颜色只取 `ArtStyleGuide.md` §8 的设计令牌（面板底 `#1A1A2E`、强调绿 `#7CFC98`、警示红 `#FF6B6B`、禁用灰 `#888`）
- [ ] 每个操作都有 ≥1 个即时反馈（视觉或音频）
- [ ] 新增文本考虑本地化（长度上限、不硬编码换行，见 `Localization.md`）
