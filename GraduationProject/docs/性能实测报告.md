# 性能实测报告

> 测量日期：2026-10-18 | 引擎：Unity 2022.3.62f3c1 | 平台：Windows 11 x64
> 测量工具：Unity Profiler（FrameTimingManager + ProfilerRecorder counters）
> 测量场景：Editor Play 模式，三关分别独立加载后取样

## 一、测量方法

1. 打开目标场景 → 进入 Play 模式 → 等待场景完全初始化（含刷怪、UI、音频）
2. `FrameTimingManager` 读取单帧 CPU/GPU 时间（`get_frame_timing`）
3. `ProfilerRecorder` 读取 `GC Allocated In Frame` / `GC Allocation In Frame Count` 等计数器
4. 每关取样 1~2 次，记录代表性数值

**测量条件说明**：Editor Play 模式下 `FrameTimingManager.CaptureFrameTimings()` 的采样在窗口
失焦/空闲时不刷新，因此多次循环采样会返回恒定值。本报告采用「场景加载完成后主动读单帧」的
方式取样，反映的是稳定运行帧而非峰值帧。

## 二、实测结果

### 2.1 帧时间

| 关卡 | CPU 帧时间 (ms) | CPU 主线程 (ms) | CPU 渲染线程 (ms) | GPU 帧时间 (ms) | 隐含帧率上限 |
|---|---|---|---|---|---|
| Level01 污染星球 | 2.02 | 0.51 | 0.43 | 0.73 | ~495 FPS |
| Level02 生态森林 | 1.93 | 0.53 | 0.41 | 0.15 | ~519 FPS |
| Level03 能源工厂 | 3.42 | 1.01 | 0.61 | 0.94 | ~292 FPS |

**结论**：三关 CPU 帧时间均 < 4 ms，GPU 帧时间均< 1 ms。
60 FPS 的预算为 16.67 ms，当前最重的一关（Level03，含 Boss）仅用掉其中 20.5%，
**「帧率稳定 60」目标达成，且有 4.9 倍余量**。

## 三、目标达成情况

| TDD 目标 | 实测 | 状态 |
|---|---|---|
| 帧率稳定 60 FPS | 三关 CPU 帧时间 ≤ 3.42 ms（预算 16.67 ms） | ✅ 达成，余量 4.9× |
| GC = 0 |每帧约 18.8 KB / 375 次分配 | ❌ **未达成** |
| 内存占用可控 |常驻 1.6~1.8 GB（Editor 含编辑器开销） | ⚠️ 待Build 版复核 |

### 3.1 GC 分配来源分析

每帧 375 次分配属「有分配但无明显卡顿」量级（18.8 KB/帧，60 FPS 下约 1.1 MB/s，
GC 压力极低，不会造成可感知的掉帧）。但距离「GC=0」有差距，可能来源：

1. **LINQ 链式调用** —— `EnemyControllerBase` / `EventCenter` 中若在 Update 路径使用
   `GetComponentsOfType(...).Where(...)` 会每次分配枚举器与闭包
2. **字符串拼接** —— HUD 数值格式化（`ToString("F0")` 每帧产生新字符串）
3. **闭包/委托** —— 事件订阅中捕获变量的 lambda 每次调用产生委托实例
4. **Unity 内部** —— `Camera.main`（每帧查找带 MainCamera 标签的物体）、`FindObjectOfType`
   这类 API 本身不分配但会触发引擎内部临时对象
5. **`new Vector2/3` 值类型装箱** —— 若传入 `object` 参数（如 `Debug.Log` 拼接、
   `SendMessage`）会装箱

**下一步定位方式**：Profiler 开启 Allocation Callstacks（本次已启用，见
`profiler_start(enable_callstacks=true)`），按 GC Alloc 排序即可逐条定位到调用栈。

### 3.2 后续优化建议（按性价比排序）

| 优先级 | 优化项 | 预期收益 |
|---|---|---|
| 高 | HUD 数值缓存：仅在数值变化时更新 Text，而非每帧 `ToString` | 消除每帧字符串分配 |
| 高 | 敌人感知/查找逻辑的 LINQ 改为缓存数组 + 手动筛选 | 消除枚举器与闭包分配 |
| 中 | `Camera.main` 缓存到静态字段 | 消除标签查找开销 |
| 中 | 事件订阅改为缓存委托实例（避免 lambda 捕获） | 消除委托分配 |
| 低 | 确认 Editor 与 Build 版差异 | Editor 含 Profiler 与编辑器开销，Build 版应显著更低 |

## 四、结论

- **性能目标整体达成**：三关帧时间均有 4.9 倍以上余量，可支撑 60 FPS 稳定运行
- **GC=0 目标未达成**：每帧 18.8 KB 分配属可接受范围，不影响帧率稳定；
  但作为毕业设计的技术指标，建议在论文中如实呈现「已定位来源、给出优化方案、
  量化优化前后对比」的分析过程，而非仅声称达标
- **内存数据需Build 版复核**：Editor 模式的 1.6~1.8 GB 含编辑器与 Profiler 开销，
  不代表最终构建产物的真实占用
