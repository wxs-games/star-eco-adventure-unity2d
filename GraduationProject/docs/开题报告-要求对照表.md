## 五、开题报告已具备的加分项（答辩时重点讲）

这些是评阅老师会看到的**实证**，务必在答辩中主动展示：

| 加分项           | 硬数据                                                                           | 怎么讲                                      |
| ------------- | ----------------------------------------------------------------------------- | ---------------------------------------- |
| **工程量超预期**    | 169 个 C# 文件 / 24,479 行 / 10 个功能模块 / 54 个动画片段 / 421 张动画帧 / 3 关场景               | 学校第 ① 条要求核「工作量」，直接给数字                    |
| **性能优化有硬成果**  | 构建产物 **1.6 GB → 333 MB**（-79%），根因定位到 Unity 对非 4 倍数（NPOT）纹理的压缩回退行为             | **这是技术含量最高的一段**，能讲清"如何用交叉统计定位"直接证明问题解决能力 |
| **零 GC 设计**   | Build 版本运行时 GC alloc = 0；事件使用 struct 传递                                       | 证明对 Unity 性能陷阱的理解                        |
| **自检与测试体系**   | `FrameworkSelfTest` 12 项运行时自检全 PASS（含存档损坏容错）；EditMode 测试 13 个用例；独立 asmdef 程序集 | 证明工程规范意识                                 |
| **美术工具链**     | 自建逐帧生成与切帧管线（连通域抠像、基线对齐、帽子刚性标尺归一），全流程可复现                                       | 体现"程序化解决美术产能"的技术思路                       |
| **武器与角色解耦架构** | 钳子作为 `ToolAnchor` 子物体 + 动画曲线驱动位置 + `m_IsActive` 曲线控制显隐 → 一套动画支持两把钳子           | 架构设计亮点，讲"为什么解耦"很能体现设计思维                  |
| **环保教育闭环**    | 8 张知识卡 + 4 组对话 + 知识图鉴 UI，污染星球→生态森林→能源工厂三关主题递进                                 | 回应学校"融入数媒特色"和"教育意义"要求                    |
