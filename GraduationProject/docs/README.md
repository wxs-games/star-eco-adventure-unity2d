## 二、文档分层与权威顺序

冲突时的取舍规则。**上位覆盖下位，下位不得与本位矛盾**。

```
第 1 层 · 事实层（唯一真相）
    Assets/Scenes/*.unity      场景文件（坐标、组件、排序）
    Assets/Settings/*.asset    配置数值
    Assets/Scripts/**/*.cs     代码行为
        ▲
        │ 一切文档必须与这层一致；不一致时改文档，不改事实
        │
第 2 层 · 总纲
    docs/GDD.md                做什么、为什么
    docs/TDD.md                用什么技术做
    docs/SystemOverview.md     切成几个系统、谁依赖谁、事件怎么流
        ▲
第 3 层 · 分岗位设计
    docs/LevelDesign.md        关卡坐标与流程
    docs/LevelArt.md           关卡画面
    docs/NarrativeDesign.md    世界观与文案
    docs/AudioDesign.md        音频规格
    docs/ArtStyleGuide.md      视觉规范
    docs/AnimationVFXSpec.md   动画与特效
    docs/CodeStandard.md       编码约定
        ▲
第 4 层 · 逐功能规范
    specs/01~11/                EARS 需求 + 设计 + 任务
        ▲
第 5 层 · 验证与记录
    docs/TestPlan.md            验收用例
    docs/性能实测报告.md         性能数据
    docs/交接文档*.md            历史记录
```

**三条硬规则**：

1. **场景 > 文档**。`LevelDesign.md` 写的坐标与场景不符时，以场景为准，然后改文档。
2. **同一关卡的三份文档必须同步改**：`LevelDesign.md`（策划）+ `LevelArt.md`（美术）+ `specs/1X-Level0X`（程序）。改一处不改另两处 = 制造漂移。
3. **改了数值必须改 `Balance/combat_units.csv`**。它是数值的唯一表格源。
