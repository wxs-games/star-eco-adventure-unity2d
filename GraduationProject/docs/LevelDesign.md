## 一、文档定位

### 1.1 三层文档的分工

| 层级 | 文档 | 回答什么问题 | 读者 |
|---|---|---|---|
| 创意层 | `LevelDesign.docx` | 这一关讲什么故事、要传达什么环保理念、大致有哪些挑战 | 策划、导师、评审 |
| **落地层** | **本文** | **每样东西放在哪、玩家按什么顺序走、多高多远、什么时候会死** | 程序、美术、自己实现时 |
| 实现层 | `Assets/Scripts/Editor/LevelXxxSetup.cs` | 怎么用代码把落地层重新生成出来 | 需要重建场景时 |

`LevelDesign.docx` 全文 22 段，三关各三小节（场景描述 / 任务与挑战 / 环保教育元素），**不含任何坐标、数量、数值、流程节点**。它是一份合格的创意案，但不足以据此实现关卡。本文补的就是这一层。

### 1.2 数据权威顺序（重要）

```
场景文件（Assets/Scenes/*.unity）  ← 最高，唯一真实
    ↓ 已发生漂移
生成脚本（Assets/Scripts/Editor/LevelXxxSetup.cs）
    ↓
本文
```

**场景与生成脚本已经不一致**（详见第八章 8.2）。本文所有坐标与尺寸均取自**场景文件实测**，不是脚本常量。重建场景前请先读 8.2。

### 1.3 单位与坐标系

| 项目 | 约定 |
|---|---|
| 单位 | 世界单位 u（1u ≈ 玩家身高的一半） |
| 坐标原点 | 多数关卡 `y=0` 为地面顶面；**平台记「顶面高度」不记中心** |
| 像素换算 | PPU = 378，1080p 下 1u ≈ 166px；角色高约 2.01u |
| 碰撞体推导 | 一律 `sprite.bounds.size × 0.9`，`offset = 0`（见 GDD §v0.3） |
| 伤害单位 | 整数「半心点」，2 点 = 1 颗心 |

## 二、通用规则

### 2.1 玩家能力包线（所有几何设计的硬约束）

这是关卡设计的地基——任何间距都必须先对照这张表。

| 能力 | 数值 | 推导结果 |
|---|---|---|
| 跑速 `MoveSpeed` | 6 u/s（加速 60 u/s²） | 满速约 0.1s 达成 |
| 跳跃初速 `JumpVelocity` | 13 u/s | — |
| 重力 `GravityScale` | 3（= 29.43 u/s²） | **最大跳跃高度 2.87u** |
| 下落倍率 `FallGravityMultiplier` | 1.6（下落 g = 47.09） | 上升 0.442s / 下降 0.349s |
| 单跳滞空 | — | **0.79s** |
| **满速水平跳距** | — | **4.75u**（不含冲刺） |
| 冲刺 `DashDistance` | 2.8u / 0.4s，空中可用 1 次 | 理论上限约 **7.5u** |
| 翻滚 `DodgeDistance` | 3u / 0.333s，无敌 0.33s | 地面闪避用 |
| 土狼时间 / 跳跃缓冲 | 0.1s / 0.1s | 容错窗口 |
| 蹬墙跳 `WallJumpVelocity` | 12 u/s（横向推 7） | 竖直可借力 |

**由此得出三条关卡设计红线：**

1. **垂直落差 > 2.87u 的地方，必须给中间落脚点**（否则跳不上去）
2. **水平空档 > 4.75u 的地方，必须给摆渡工具或冲刺余地**（否则过不去）
3. **空档 > 7.5u 时冲刺也救不了，只能靠机关**（第二关的河、第三关的尖刺带都属于这一类）

### 2.2 生命与伤害

| 项目 | 值 |
|---|---|
| 玩家生命 | 10 半心点 = 5 颗心 |
| 受击无敌 | 1s（硬直 0.6s，击退 6 u/s） |
| 夹钳伤害 | 2 半心点 / 段，三段连击，第三段击退 6 |
| 地刺 / 坠落 / 溺水 | 999（一击必死，且地刺用 Stay 持续结算，无敌期后立刻再结算——无法硬闯） |
| 掉落 / 致死差别 | 「掉出地板」死因记为坠落；「踩刺」死因记为陷阱；两者共用同一伤害流水线 |

### 2.3 失败与重生

- **实际实现：死亡即本局失败，整关重开**。`LevelManager.Update` 检测到 `_player.IsDead` → `SetState(Failed)` → 播 `LevelFail` → 弹结算面板；面板「重新开始」走 `RestartLevel()`，内部 `SceneManager.LoadScene(scene.buildIndex)` 重载本关。
  - 为什么不做原地重生：已净化的净污源、永久熄灭的敌人、已开的门等运行时状态是单向的，原地重置无法真正回到初始态；重载是唯一彻底的方案（`LevelManager.cs:150` 注释原文）。
- **检查点系统未实现**：设计稿写的是「净化过的净化塔自动激活成为检查点」，但代码里没有 `Checkpoint.cs`、场景里没有 `CP_*` 对象、`SfxId.Checkpoint` 无调用点。当前只有「整关重开」一条路。补做需三件：触发体脚本 + 场景摆放 + `LevelManager` 保存重生锚点（并把 `RestartLevel` 拆成「重载」与「回锚点」两条）。
- 出生点：`LevelConfig.SpawnPoint` 已于 2026-10-30 **废弃**，出生点改为「场景里 Player 预制体实例的实际摆放位置」——编辑器里看到的位置就是唯一的真实，运行时不再按配置瞬移。**改出生点 = 在场景里拖动 Player 并保存场景**，改配置无效。
- 掉出地板边界由全宽 `KillZone_Fall`（y = −8）兜底，不会无限下坠

| 关卡 | 实际出生坐标（场景 Player 位置） | 配置里的 `SpawnPoint`（已废弃，仅存档） |
|---|---|---|
| L1 | (−17.68, 1.12) | (−8, 2) |
| L2 | (−26.00, 1.12) | (−26, 2) |
| L3 | (−18.60, 1.50) | (−12, 2) |

## 四、第一关：污染初现的星球

### 4.1 设计目标

- **教学关**：把跑、跳、攻击、净化四个动词在一局内教完，不设失败陷阱
- 用最少的机关种类降低认知负担，节奏靠「净化值推进 → 背景变绿」给正反馈
- 空间上左右对称（左半教学、右半战斗），给玩家「往回走也安全」的心理底

**关于平台的重要说明**：两侧平台（L1/L2、R1/R2）是**可选探索点**，不在主路上——地面从 −20 到 +20 全程连通，玩家可以一次都不跳就走完全关。平台上的奖励是一块装饰路牌（`Decor_Sign_L01W` / `Decor_Sign_R01R`），没有独占道具。这是刻意设计：第一关的「跳」只用于建立动作印象，不作为门槛。

**节奏特征**：前 60 秒无敌人（②③④），只顾跑跳读文本；从 ⑤ 开始给净化，⑦⑧ 才给压力。这是刻意的「无威胁教学段」。

## 五、第二关：生态失衡的森林

### 5.1 设计目标

- **解谜关**：用一条 14u 宽的河把地图切成两半，逼玩家先理解「清堵塞 → 涨水 → 木筏浮起」的因果链
- 首次引入「救人」这一非战斗交互（E 键），让环保从「清理」扩展到「救助」
- 双岸结构制造「回不去」的紧张感：过了河就只能从右岸打完全部目标

**当前：0 个载体。这是三关中唯一的缺口。**

```
难度
```

| 维度 | L1 | L2 | L3 |
|---|---|---|---|
| 新增机制数 | 2（净化、碎裂平台） | 3（救人、水位、渡河） | 5（移动平台、尖刺、拉杆、可破坏、Boss） |

**结论**：概念案里约 3/4 的条款已落地，剩下的是「美术表现层」（枯萎树木、管道泄漏）与「第二关教育内容」两类。

### 8.2 生成脚本与场景已漂移（重要）

`Level01Setup.cs` / `Level02Setup.cs` / `Level03ExtendSetup.cs` 的**坐标常量已不能重建出当前场景**。实测差异举例（第二关）：

| 物件 | 脚本常量 | 场景实际 | 差异 |
|---|---|---|---|
| `PlatformL1` | (−24.0, 顶面 1.40) | (−24.5, 顶面 **2.58**) | 高了 1.18u |
| `PlatformR1` | (22.0, 顶面 1.40) | (20.5, 顶面 **2.89**) | 高了 1.49u |
| `SpawnAnchorA` | (16.0) | (**−10.0**) | 换到左岸了 |
| `SpawnAnchorB` | (26.43) | (**16.0**) | 换了位置 |
| `Garbage2` | (18.3) | (17.0) | 左移 1.3u |
| 平台厚度 | 2f 宽 | 3.0 / 2.08 宽，0.18 厚 | 尺寸不同 |

**影响**：三关的菜单重建都是「场景已存在就跳过」，所以短期内不会误触发。但如果哪天删了场景重跑生成脚本，会得到一个**几何不同、手感不同**的关卡（例如 L2 的 L1 顶面从 2.58 降到 1.40，碎裂平台的教学强度就变了）。

**建议**：要么把场景的最终值回写进脚本常量，要么在脚本里加一行注释说明「本脚本已降级为初始灰盒，真实布局以场景为准」。这一项需要单独排期，本文档不擅自改代码。
