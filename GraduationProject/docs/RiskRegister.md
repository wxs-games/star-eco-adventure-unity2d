# 风险登记表 · RiskRegister

> 版本：v1.0 | 2026-10-30 | 维护：制作人（技术项由主程序复核）
> 定位：**全项目唯一的风险台账**。每条风险有编号、概率、影响、等级、应对与状态；修好了就标"已闭环"并留证据，不删行。
> 与相邻文档的分工：`TDD.md` §4 是架构风险（偏技术选型）；`TestPlan.md` §7 是已知缺陷（偏验收）；本文是**跨岗位的全量台账**，是前两者的并集加上排期/流程类风险。

---

## 1. 分级标准

### 1.1 概率 × 影响 = 等级

| 概率 \ 影响 | 低（体验瑕疵） | 中（局部功能受损） | 高（卡关/崩溃/交付失败） |
|---|---|---|---|
| **高（已发生或必然发生）** | P3 | P1 | **P0** |
| **中** | P3 | P2 | P1 |
| **低** | P3 | P3 | P2 |

### 1.2 处理时限（毕设节奏）

| 等级 | 含义 | 时限 |
|---|---|---|
| **P0** | 影响可玩性/交付，必须马上处理 | 当轮 |
| **P1** | 影响体验或答辩说服力 | 本轮或下一轮 |
| **P2** | 可接受的技术债/体验债 | 有空就做，答辩前说明 |
| **P3** | 记录在案即可 | 不做 |

### 1.3 状态口径

| 状态 | 含义 |
|---|---|
| **已闭环** | 已修，且附证据（提交号/文档章节/实测结论） |
| **已缓解** | 未根治，但影响被控制住 |
| **待处理** | 确认存在，未动手 |
| **监测中** | 目前不触发，条件变化后会变成问题 |
