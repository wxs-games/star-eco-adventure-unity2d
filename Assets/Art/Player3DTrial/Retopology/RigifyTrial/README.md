# Rigify 试绑与关节测试

使用本机 Blender 5.1.2 自带 Rigify basic human metarig，按主角头身、肩肘腕和髋膝踝位置拟合；生成222根控制、机构和变形骨骼。这不是222根全部参与蒙皮。

原模型热权重失败；采用0.018 m体素代理，平滑5次，在代理上做 Blender 自动热权重成功（14972个代理顶点，未赋权0）。用最近表面三角形重心插值，将代理权重转移回原始4745四边面身体，不修改其原始UV、贴图。眼睑刚性绑定到头部变形骨骼。原模型与旧试验文件保留。

文件：DCC~/Player_Rigify_Tested.blend 为带控制骨架、关节诊断动作的测试版；Player_Rigify_JointTests.fbx 为烘焙导出验证；JointTests.png 是六种测试姿势。rig_check.json、pose_check.json 记录权重覆盖与姿势检查。

已检查静止不漂移和左侧抬臂/弯肘/屈膝/抬腿/脚踝六种状态；不是所有角度、双侧或组合姿势的最终验收。近看肩部/裤腿仍可能有压缩，代理权重需继续针对极端姿势精修。没有把旧五个程序动画直接套上新骨架，尚未制作成熟动作重定向。未替换正式游戏玩家。

Rigify UI 脚本若受 Blender 安全设置限制，基础骨骼和变形仍可检查；不需要开启任意外部脚本来查看截图或模型。

## 导出验证发现的缺口

Unity 能导入骨架与2.5秒片段，但在0和0.5秒采样时身体顶点没有变化，诊断动画导出尚未通过。FBX仅为排查产物，不作为可播放绑定的交付。RigifyTrial.blend 保留原控制骨架；Rigify_Tested.blend 是烘焙试验文件，试过清除约束，不应作为继续编辑控制Rig的来源。后续需定位控制曲线与变形骨骼烘焙的传递问题。控制骨架与蒙皮在Blender逐项摆姿截图通过，不代表Unity动画链路通过。
